// Files allowed to use an API that BannedSymbols.txt bans. One file per line: its path from the
// repository root, a semicolon, and why that file needs it. docs/DOTNET.md explains the rules.
//
// Only the audited classes that exist to do these things safely belong here:
//   SecureStore      the data folders: born locked, checked through a handle, written atomically
//   ProfileReader    reading user profiles by handle, without following links
//   the registry primitive, with an explicit 64-bit view
//   the trusted process runner, for the few Windows tools that have no API
//   the service client, the one place an HTTP request is sent, with the proxy it chose for it
//
// In a listed file, each use sits between "#pragma warning disable RS0030 // <why>" and
// "#pragma warning restore RS0030", around as few lines as possible. Adding a file here, or a use to
// a listed file, needs the maintainer's review. tests/Engramic.Baseline.Invariants.Tests enforces this.
//
// The same goes for a sensitive Win32 function in src/Engramic.Baseline.Windows/NativeMethods.txt (one
// that opens files by path, touches the registry, starts a process and so on): only a listed file may
// name it, and only inside such a pragma region.

src/Engramic.Baseline.Windows/WindowsRegistry.cs; the registry primitive: opens a key read-only in the view its caller names and reads one value as stored
src/Engramic.Baseline.Windows/SecureStore.cs; SecureStore, the machine data folder: opens ProgramData by its path as itself and checks its final path, opens everything below it one name at a time relative to a held folder's handle and as itself (never through a link), creates folders and files exclusively with their security set in the same call, renames untrusted items aside and deletes links, trees and its own files through their handles, and asks the known-folder API for ProgramData, whose answer follows the environment, checking it against the Windows drive
src/Engramic.Baseline.Windows/ServiceClient.cs; the service client: sends each request through an HttpClient and handler of its own, with the proxy it chose for that request and never .NET's default proxy, no redirects or cookies, and the Windows sign-in only for a proxy allowed it
