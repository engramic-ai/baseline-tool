This release carries on making the audit accurate on devices managed by Intune: checks now read a setting from Intune, Group Policy and the device itself, and say which one applies.

**Settings applied by Intune or Group Policy are read where they live.** Several checks looked in only one place, so a setting a policy applied was missed, or a local value the policy overrides was reported instead:

- **Windows SmartScreen (MP-06)** reads the Intune SmartScreen settings as well as Group Policy. It no longer reports SmartScreen as on when nothing sets it.
- **Remote Assistance (SC-11)** and **Remote Desktop (FW-04)** read the policy that overrides the local setting, whether Group Policy or Intune applied it. Remote Assistance also checks "Offer Remote Assistance".
- **Windows LAPS (SC-02, UA-09)** is found whether Intune or Group Policy configures it. SC-02 now fails when LAPS manages a named admin account while the built-in Administrator stays enabled.
- **Password expiry (UA-05)** reads an Intune password expiry as well as the local policy, and passes when the only local account is managed by Windows LAPS, as the password length check already does.

Each of these results names where the setting came from, and lists the values read as evidence. When two policies disagree the report says so. When a policy controls a setting, the report tells you which policy to change, and the automatic fix is not offered, since the policy would undo it.

**Other fixes:** firewall rules that share a display name are reported separately, each with its own rule name, and every finding in a report now has a unique ID.
