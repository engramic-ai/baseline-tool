This release makes the audit more accurate on devices managed by Intune, finds AI browser extensions, and hardens how the tool keeps its own files.

**Intune-managed devices are read correctly.** Several checks looked only where Group Policy or the local policy keep their settings, so policies Intune had applied were reported as missing:

- **Windows Hello PIN length (SC-08)** now reads Windows Hello for Business policies from Intune, whether they target devices or users.
- **Local password length (UA-04)** passes when the only local account is managed by Windows LAPS, and counts the minimum length an Intune password or compliance policy enforces.
- **Application control (MP-09)** now sees AppLocker rules deployed by Intune, and tells enforced rules apart from audit-only ones.
- **Office macros (MP-08)** now read the signed-in user's policies when you run the audit elevated with a separate admin account. Intune and Group Policy set these per user, so the tool used to read the admin's settings instead. Other per-user settings (the screen-saver lock, per-user installs, Store apps and WSL) are read the same way.
- **Automatic updates (SU-02)** reads your Intune update ring. When an old "turn off automatic updates" value conflicts with it, the report says so and suggests where that value usually comes from. It also warns when the update deadline and grace period add up to the full 14-day patching window.

**AI browser extensions and AI browsers are found** and listed with the other AI tools, so you can record MFA for the services they reach.

**The tool's own files are harder to tamper with.** The data folder under ProgramData is created locked so only administrators and SYSTEM can change it. A folder someone else made is moved aside, not trusted. An elevated audit can no longer be steered through environment variables or PATH. The Intune install script never downgrades an existing install unless asked.

**Other fixes:** the Intune compliance scripts read their JSON as UTF-8. A device whose scheduled audit keeps failing is flagged, but one failed run isn't. Credentials in MCP configs never appear in summaries. Network requests go through one client that supports proxies.
